## 1. Provenance Architecture Specification

Every artifact, inference result, and decision generated by TRUSTGATE AI is bound by an immutable, cryptographically verifiable 8-tuple:
```
USER -> CASE -> DOCUMENT -> PROCESSING_RUN -> IMAGE_HASH -> MODEL -> EVIDENCE -> RESULT
```

### Immutable Bindings
1. **User Identity (`user_id`)**: Authenticated JWT subject claiming ownership of the screening session.
2. **Case Container (`case_id`)**: Enterprise multi-document case identifier (`TG-CASE-XXXX`).
3. **Document Entity (`document_id`)**: Specific credential uploaded within the case container.
4. **Processing Run (`processing_run_id`)**: Monotonically unique execution ID (`RUN-YYYY-XXXX`). Each retry or document re-upload creates an independent run ID; runs are never overwritten or reused.
5. **Image Hash (`image_hash`)**: SHA-256 cryptographic digest calculated directly over raw image byte streams before any processing or compression.
6. **Model Fingerprint (`model_version`)**: Version identifier of the AI/CV models (`explainable-v1`, `tesseract-js-v5`, `ela-forensics-v2`).
7. **Evidence Trail (`evidence_records`)**: Raw OCR bounding boxes, MRZ checksum calculations, ELA difference matrices, and facial landmark coordinates.
8. **Final Decision (`decision_payload`)**: Signed composite verdict (`PASS`, `REVIEW`, `FAIL`, `INCONCLUSIVE`) with explainable risk factor weights.

## 4. Cross-Case Contamination Detection Audit
The test harness executed 100 sequential and concurrent screening runs while monitoring for:
1. **Stale Memory Bleeding**: Ensuring extracted fields from Case N do not appear in Case N+1.
2. **Cached Result Reuse**: Ensuring identical or similar document inputs generate independent `processing_run_id`s.
3. **Audit Event Overwriting**: Ensuring tamper-evident audit logs preserve discrete event sequences per case.

**Audit Result**: Across all 100 cases, zero cross-case contamination incidents were detected (`crossContaminationDetected: false`, `provenanceValid: true` for 100/100 cases).
